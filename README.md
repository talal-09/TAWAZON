# توازن | TAWAZON

### نظام ذكي لتحسين تجربة تسجيل المقررات الجامعية

</div>

## فكرة المشروع

**توازن** مشروع يهدف إلى مساعدة الجامعات على تحسين تخطيط المقررات والشعب الدراسية، ومعالجة المشكلات التي يواجهها الطلاب أثناء التسجيل.

تظهر هذه المشكلات عندما تتعارض أوقات المحاضرات، أو تمتلئ شعب المقررات المطلوبة، أو لا تتناسب المقاعد المتاحة مع احتياجات الطلاب. وقد يؤثر ذلك في تقدم الطالب ضمن خطته الدراسية، خصوصًا عند الحاجة إلى مقرر إجباري أو متطلب أساسي للتخرج.

يقدم توازن تصورًا لنظام يساعد الجهات الأكاديمية على فهم احتياجات الطلاب واكتشاف مشكلات التسجيل مبكرًا، ثم دعم اتخاذ قرارات أفضل بشأن الشعب والمقاعد والجداول.

## الفئة المستفيدة

- الجامعات والأقسام الأكاديمية.
- عمادات القبول والتسجيل.
- طلاب الجامعات.
- الطلاب المتوقع تخرجهم.

## الهدف

- تحسين تجربة تسجيل المقررات.
- تقليل تعارضات المحاضرات.
- تحسين توزيع المقاعد والشعب.
- دعم التخطيط الأكاديمي.
- الحد من احتمال تأخر الطلاب بسبب مشكلات التسجيل.

## حالة المشروع

المشروع حاليًا في مرحلة تطوير بروتوتايب للمشاركة في هاكثون.

## التشغيل المحلي (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

لتشغيل الاختبارات: `python manage.py test`.

لإضافة بيانات افتراضية للعرض: `python manage.py seed_demo`. يمكن إعادة تشغيل الأمر دون تكرار السجلات، ولا يغيّر البيانات الموجودة.

لإضافة 100 طالب افتراضي بأرقام جامعية من 9 خانات تبدأ بـ`439` إلى `446`، مع 5 مقررات و10 شعب و200 طلب تسجيل: `python manage.py seed_demo --large`. طلاب `439` موسومون كمتوقع تخرجهم ليحصلوا على أولوية التحسين. تُضاف البيانات في فصل «فصل توازن الموسع 2026» مستقل عن المثال الصغير، ويمكن تكرار الأمر دون مضاعفة السجلات.

افتح `/admin/` وسجّل الدخول بحساب إدارة، ثم افتح `/optimizer/` واختر الفصل الدراسي واضغط «احسب النتيجة». إنشاء حساب إدارة محلي جديد: `python manage.py createsuperuser`. تشغيل التحسين يتطلب صلاحية عرض وإنشاء تشغيلات التحسين.

## عرض الهاكثون: ماذا لو؟

1. شغّل `python manage.py seed_demo --large` ثم `python manage.py runserver`.
2. سجّل الدخول من `/admin/` وافتح `/optimizer/`، واختر «فصل توازن الموسع 2026» في «الوضع الحالي» واحسب النتيجة.
3. في «ماذا لو زادت المقاعد؟» اختر الفصل نفسه، ثم شعبة ممتلئة وأضف عددًا من 1 إلى 50 مقعدًا، واضغط «قارن السيناريو».
4. اقرأ مقارنة المسند دون الزيادة وبعدها، والطلبات التي استفادت، وطلبات المتوقع تخرجهم. افتح جداول المقترحات والطلبات غير الموزعة عند الحاجة.

السيناريو يحسب السعة الإضافية في الذاكرة فقط، ويحافظ على الطلبات التي حصلت على مقعد في الحساب الأساسي. لا يغير `Section.capacity` أو `Enrollment`. النتيجة محفوظة للعرض لاحقًا. يتطلب التشغيل صلاحيتَي `view_optimizationrun` و`add_optimizationrun`؛ صاحب صلاحية العرض فقط لا يستطيع تشغيل الحساب. النموذج يتحقق من الفصل والشعبة وحد المقاعد، وطلبات POST محمية بـCSRF.

تعرض النتيجة سببًا لكل طلب لم يجد مقعدًا، مع علامة للطالب المتوقع تخرجه أو المقرر المطلوب للتخرج. تُحفظ الأسباب وقت التشغيل؛ وإذا تغيرت بيانات الشعب لاحقًا، شغّل التحسين مجددًا للحصول على تفسير حديث.

للتطوير المحلي، ضع `DJANGO_SECRET_KEY=<مفتاح جديد>` في `TAWAZON/.env`. هذا الملف مستبعد من Git، ويقرأه المشروع تلقائيًا. لا تستخدم مفتاحًا ظهر سابقًا في GitHub.

قاعدة SQLite والبيئة الافتراضية وملفات الأسرار محلية ولا تُرفع إلى GitHub. عند النشر، عيّن `DJANGO_SECRET_KEY` من البيئة، واضبط إعدادات الإنتاج قبل تشغيل الخادم.
