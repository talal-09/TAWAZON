# توازن | TAWAZON

### نظام ذكي لتحسين تجربة تسجيل المقررات الجامعية

</div>

## فكرة المشروع

**توازن** مشروع يهدف إلى مساعدة الجامعات على تحسين تخطيط المقررات والشعب الدراسية، ومعالجة المشكلات التي يواجهها الطلاب أثناء التسجيل.

تظهر هذه المشكلات عندما تتعارض أوقات المحاضرات، أو تمتلئ شعب المقررات المطلوبة، أو لا تتناسب المقاعد المتاحة مع احتياجات الطلاب. وقد يؤثر ذلك في تقدم الطالب ضمن خطته الدراسية، خصوصًا عند الحاجة إلى مقرر إجباري أو متطلب أساسي للتخرج.

يقدم توازن تصورًا لنظام يساعد الجهات الأكاديمية على فهم احتياجات الطلاب واكتشاف مشكلات التسجيل مبكرًا، ثم دعم اتخاذ قرارات أفضل بشأن الشعب والمقاعد والجداول.

## الفئة المستفيدة

- الجامعات والأقسام الأكاديمية.
- عمادات القبول والتسجيل.
- طلاب الجامعات.
- الطلاب المتوقع تخرجهم.

## الهدف

- تحسين تجربة تسجيل المقررات.
- تقليل تعارضات المحاضرات.
- تحسين توزيع المقاعد والشعب.
- دعم التخطيط الأكاديمي.
- الحد من احتمال تأخر الطلاب بسبب مشكلات التسجيل.

## حالة المشروع

المشروع حاليًا في مرحلة تطوير بروتوتايب للمشاركة في هاكثون.

## التشغيل المحلي (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py prepare_showcase
python manage.py runserver
```

لتشغيل الاختبارات: `python manage.py test`.

لإضافة بيانات افتراضية للعرض: `python manage.py seed_example`. يمكن إعادة تشغيل الأمر دون تكرار السجلات، ولا يغيّر البيانات الموجودة.

لإضافة 100 طالب افتراضي بأرقام جامعية من 9 خانات تبدأ بـ`439` إلى `446`، مع 5 مقررات و10 شعب و200 طلب تسجيل: `python manage.py seed_example --large`. طلاب `439` موسومون كمتوقع تخرجهم ليحصلوا على أولوية التحسين. تُضاف البيانات في فصل «فصل توازن الموسع 2026» مستقل عن المثال الصغير، ويمكن تكرار الأمر دون مضاعفة السجلات.

افتح `/` أو `/optimizer/` لرؤية نتيجة المثال دون دخول. صفحة `/academics/` تعرض رحلة البيانات والطلب والسعة لكل مقرر. لإنشاء حساب إدارة محلي: `python manage.py createsuperuser`. تشغيل التحسين يتطلب حساب موظف مع صلاحيتَي `view_optimizationrun` و`add_optimizationrun`؛ تفاصيل الطلاب والتصدير متاحة لموظف يملك صلاحية العرض.

يمكن إنشاء حساب عادي من `/register/`، ثم الدخول من `/login/` والخروج من زر «خروج». الحسابات الجديدة لا تحصل على صلاحيات إدارة تلقائيًا. يمكن للموظف المخوّل استخدام صفحة الدخول نفسها بدل واجهة إدارة Django. لإنشاء أول حساب إداري أو منح الصلاحيات استخدم أمر `createsuperuser` أو إدارة المستخدمين.

لتفعيل حساب `talal1` كمدير محدود من Shell في قاعدة البيانات التي يعمل عليها الموقع، شغّل `python manage.py grant_tawazon_manager talal1` بعد إنشاء الحساب وتشغيل `migrate`، ثم سجّل الخروج والدخول. يتيح ذلك تشغيل السيناريوهات وإعادة ضبط المثال وإدارة المقررات من `/academics/` دون منح صلاحية superuser. يمكن إضافة مقرر وتعديل رمزه واسمه وساعاته، وحذف مقرر غير مرتبط فقط. المقرر المرتبط بشعبة أو طلب أو متطلب أو طالب مكتمل لا يُحذف حفاظًا على البيانات. إضافة مقرر وحدها لا تغيّر التحسين؛ يحتاج إلى شعبة وطلبات تسجيل. لا تتطلب هذه الميزة ترحيلات جديدة.

## عرض الهاكثون: ماذا لو؟

عند تشغيل المشروع على Replit، يضيف ملف `replit.nix` مكتبة C++ التي تحتاجها NumPy وOR-Tools. بعد استيراد آخر تحديث، أعد فتح Shell وتحقق عبر `python -c "import numpy; from ortools.sat.python import cp_model; print('OK')"` قبل تشغيل الترحيلات وتجهيز المثال.

1. شغّل `python manage.py prepare_showcase` ثم `python manage.py runserver`. يمكن تكرار الأمر دون تكرار نتيجة البيانات نفسها.
2. افتح الصفحة الرئيسية وشاهد المثال المحفوظ: 140 ← 150 من 200 طلب في بيانات العرض الحالية.
3. سجّل الدخول كموظف مخوّل لتجربة التوزيع الأساسي، زيادة المقاعد، فتح شعبة جديدة، أو تغيير موعد شعبة.
4. راجع حالة الحل، التوصيات الثلاث، والتفسيرات المحتملة. استخدم البحث وتصفية الأولوية وتصدير CSV.

السيناريو يحسب الزيادة أو الشعبة أو الموعد في الذاكرة فقط، ويحافظ على الطلبات التي حصلت على مقعد في الحساب الأساسي. لا يغير `Section` أو `MeetingTime` أو `Enrollment`. تُحفظ لقطة للحقول المعروضة، مع بصمة البيانات ونسخة سياسة المحرك. طلبات POST محمية بـCSRF، والنماذج تتحقق من الفصل والشعبة والسعة والموعد.

تعرض النتيجة «تفسيرًا محتملًا» لكل طلب لم يجد مقعدًا، مع أولوية الطالب والمقرر. سياسة التحسين بالترتيب: المقررات المطلوبة للتخرج، طلبات المتوقع تخرجهم، عدد الطلاب الحاصلين على مقرر واحد على الأقل، ثم إجمالي الطلبات. القيود المطبقة: السعة، تعارض الوقت، المتطلبات السابقة، وحد الساعات. لا تمثل النسخة الأولى توفر المدرسين والقاعات والتكلفة أو موافقات القسم. `OPTIMAL` تعني ثبوت الأفضلية وفق القيود المدخلة؛ `FEASIBLE` أفضل حل وجد خلال المهلة فقط.

زر «إعادة ضبط المثال» ينشئ فصل مثال ونتيجة جديدين ويحفظ النتائج السابقة. يحتاج حساب موظف بصلاحيات إضافة فصل وعرض وإضافة تشغيل. لا يمس الفصول غير الافتراضية.

للتطوير المحلي، ضع `DJANGO_SECRET_KEY=<مفتاح جديد>` في `TAWAZON/.env`. هذا الملف مستبعد من Git، ويقرأه المشروع تلقائيًا. لا تستخدم مفتاحًا ظهر سابقًا في GitHub.

قاعدة SQLite والبيئة الافتراضية وملفات الأسرار محلية ولا تُرفع إلى GitHub. للنشر استخدم `TAWAZON.settings_production` ومتغيرات `DJANGO_SECRET_KEY` و`DJANGO_ALLOWED_HOSTS` و`DJANGO_CSRF_TRUSTED_ORIGINS` (أصل HTTPS). افحص `python manage.py check --deploy --settings=TAWAZON.settings_production`. إعدادات الإنتاج تفرض HTTPS والكوكيز الآمنة وHSTS. اضبط `DJANGO_TRUST_PROXY_HTTPS=1` فقط خلف وكيل موثوق يكتب `X-Forwarded-Proto`. قدّم الملفات الثابتة من خادم النشر واحتفظ بقاعدة البيانات في تخزين دائم؛ SQLite مناسب للعرض المحدود.
